11  JavaScript och DOM

Orientering om Ecmaskript (JavaScript) och dokumentobjektsmodellen (DOM).

Kapitlets mål – efter kapitlet kan du:

  • förklara vad JavaScript och ECMAScript är, och vilken roll de har på en webbsida,
  • förklara vad DOM är och hur den skiljer sig från HTML-koden,
  • läsa och ändra element på en sida med JavaScript,
  • reagera på klick och andra händelser,
  • bygga enkla, tillgängliga funktioner som en mobilmeny och en temaväxlare,
  • förklara principen om progressiv förbättring.

Det här kapitlet är en orientering. Du ska förstå vad JavaScript gör och kunna använda det i enkla fall. Programmering på djupet kommer i senare kurser.

11.1 JavaScript och ECMAScript

JavaScript skapades 1995 på tio dagar för webbläsaren Netscape. I dag är det världens mest använda programspråk och körs i alla webbläsare – och även på servrar.

ECMAScript är namnet på standarden för JavaScript. Den skrivs av en kommitté (TC39) inom organisationen Ecma International och kommer i en ny version varje år: ES2015, ES2016 … Versionen från 2015 var den stora förändringen som gav det moderna JavaScript du ser i dag.

JavaScript och Java har inget med varandra att göra, förutom namnet.

11.2 DOM – sidan som ett träd

När webbläsaren läser HTML bygger den ett träd av objekt i minnet: DOM (Document Object Model).

<body>
  <h1>Kvarnens café</h1>
  <ul>
    <li>Kaffe</li>
    <li>Te</li>
  </ul>
</body>
document
└── html
    └── body
        ├── h1
        │   └── "Kvarnens café"
        └── ul
            ├── li
            │   └── "Kaffe"
            └── li
                └── "Te"

Varje del av trädet är en nod. JavaScript kan läsa och ändra trädet, och webbläsaren ritar om sidan direkt.

NoteraVisa sidkälla och Elements visar olika saker

Visa sidkälla (Ctrl+U) visar HTML-koden som servern skickade. Fliken Elements i utvecklarverktygen visar DOM:en just nu – efter att webbläsaren lagat fel och JavaScript ändrat i den. På många moderna webbplatser skiljer de sig mycket.

defer betyder: ladda filen nu, men kör den först när hela HTML:en är inläst. Då finns alla element när skriptet letar efter dem.

11.4 Grunderna

// Variabler
const namn = "Kvarnens café";     // kan inte ändras
let antal = 0;                    // kan ändras
antal = antal + 1;

// Text med variabler (backticks)
console.log(`Välkommen till ${namn}!`);

// Villkor
const timme = new Date().getHours();
if (timme < 10) {
  console.log("God morgon!");
} else {
  console.log("Hej!");
}

// Funktion
function dubbla(tal) {
  return tal * 2;
}

console.log skriver ut i konsolen i utvecklarverktygen. Det är ditt viktigaste felsökningsverktyg.

11.5 Hitta och ändra element

const rubrik = document.querySelector("h1");           // första som matchar (CSS-selektor)
const knappar = document.querySelectorAll(".knapp");   // alla som matchar

rubrik.textContent = "Välkommen!";      // byt text
rubrik.classList.add("markerad");       // lägg till en klass
rubrik.classList.toggle("dold");        // av/på
rubrik.setAttribute("lang", "en");      // ändra ett attribut

Ändra hellre klasser än stilar direkt. Då ligger utseendet kvar i CSS:en, där det hör hemma.

11.6 Händelser

En händelse (event) är något som händer: ett klick, en tangent, att ett formulär skickas. Du reagerar med addEventListener:

const knapp = document.querySelector("#visa-mer");

knapp.addEventListener("click", () => {
  console.log("Någon klickade!");
});

Vanliga händelser: click, input (text ändras i ett fält), change, submit, keydown.

11.7 Exempel 1: Mobilmeny

I mobilen vill vi dölja menyn bakom en knapp.

<header class="sidhuvud">
  <a href="index.html" class="logga">Kvarnens café</a>
  <button class="menyknapp" aria-expanded="false" aria-controls="huvudmeny">
    Meny
  </button>
  <nav>
    <ul id="huvudmeny" class="meny">
      <li><a href="index.html">Hem</a></li>
      <li><a href="meny.html">Meny</a></li>
      <li><a href="kontakt.html">Kontakt</a></li>
    </ul>
  </nav>
</header>
.menyknapp { display: none; }

/* Bara i mobil, och bara när JavaScript fungerar */
@media (max-width: 47.99rem) {
  .js .menyknapp { display: block; }
  .js .meny { display: none; }
  .js .meny.oppen { display: block; }
}
js/main.js
// Säg till CSS:en att JavaScript fungerar
document.documentElement.classList.add("js");

const menyknapp = document.querySelector(".menyknapp");
const meny = document.querySelector("#huvudmeny");

menyknapp.addEventListener("click", () => {
  const oppen = meny.classList.toggle("oppen");
  menyknapp.setAttribute("aria-expanded", oppen);
});

Lägg märke till:

  • Det är en riktig <button>, så den fungerar med tangentbord och skärmläsare.
  • aria-expanded talar om för skärmläsare om menyn är öppen eller stängd.
  • Klassen js på <html> gör att menyn bara döljs om JavaScript fungerar. Utan JavaScript syns menyn som vanligt.

11.8 Progressiv förbättring

Det sista är en viktig princip: progressiv förbättring (progressive enhancement). Bygg först något som fungerar med bara HTML. Lägg till CSS för utseendet. Lägg till JavaScript för att göra det bättre – inte för att det ska fungera alls.

JavaScript kan saknas eller misslyckas oftare än man tror: en dålig uppkoppling som avbryter nedladdningen, ett fel i ett skript, en blockerare, ett gammalt system. Innehållet ska ändå gå att läsa och länkarna gå att följa.

11.9 Exempel 2: Är kaféet öppet nu?

<p id="oppet-nu" hidden></p>
js/main.js
const oppetNu = document.querySelector("#oppet-nu");

if (oppetNu) {
  const nu = new Date();
  const dag = nu.getDay();        // 0 = söndag, 6 = lördag
  const timme = nu.getHours();

  const helg = dag === 0 || dag === 6;
  const oppnar = helg ? 9 : 7;
  const stanger = helg ? 16 : 18;

  if (timme >= oppnar && timme < stanger) {
    oppetNu.textContent = `Öppet nu – välkommen in! Vi stänger kl. ${stanger}.`;
  } else {
    oppetNu.textContent = `Stängt just nu. Vi öppnar kl. ${oppnar}.`;
  }
  oppetNu.hidden = false;
}

Elementet är dolt (hidden) i HTML:en och visas först när JavaScript har skrivit en text. Utan JavaScript syns ingen tom ruta – öppettiderna står ju ändå i tabellen.

11.10 textContent eller innerHTML?

element.textContent = "Text";                // sätter text – säkert
element.innerHTML = "<strong>Text</strong>"; // tolkar som HTML – var försiktig

Om texten kommer från en användare kan innerHTML låta någon smyga in kod på sidan. Det kallas XSS och tas upp i kapitel 12. Använd textContent när du sätter text.

Tips🔬 Labb 11.4 – Öppet nu
  1. Lägg in “Öppet nu”-skylten på Kvarnens startsida.
  2. Testa båda fallen. Tips: ändra tillfälligt timme till ett fast tal, eller ändra datorns klocka.
  3. Lägg till en färgmarkering med en klass (.oppet, .stangt) – men glöm inte att informationen inte får ligga bara i färgen.
Tips🔬 Labb 11.5 – Temaväxlare

  1. Lägg en knapp “Mörkt läge” i sidfoten.

  2. Vid klick: växla klassen morkt på <html>. Skriv CSS som byter dina färgvariabler när klassen finns.

  3. Spara valet i webbläsaren så att det finns kvar på nästa sida:

    localStorage.setItem("tema", "morkt");     // spara
localStorage.getItem("tema");              // läsa

  4. Uppdatera knappens text och aria-pressed.

Facit till instuderingsfrågorna

  1. JavaScript är språket; ECMAScript är standarden (från Ecma International/TC39) som beskriver det.
  2. HTML: innehåll/struktur, CSS: utseende, JS: beteende/interaktivitet.
  3. En trädstruktur av objekt (noder) som webbläsaren bygger av HTML:en och som JS kan läsa/ändra. Träd: ul → tre li → textnoder.
  4. Elements visar aktuell DOM: webbläsaren har rättat fel i HTML:en och JavaScript kan ha lagt till/ändrat innehåll efter inläsning.
  5. Skriptet laddas parallellt men körs först när HTML:en tolkats färdigt, så alla element finns.
  6. querySelector hittar första elementet som matchar en CSS-selektor. addEventListener kör en funktion när en händelse inträffar på elementet.
  7. Utseendet stannar i CSS (separation of concerns), lättare att underhålla och ändra.
  8. Grundfunktionen byggs med HTML så att den fungerar för alla; CSS och JS lägger till förbättringar. Ex: menyn syns utan JS och blir en utfällbar meny med JS.
  9. button är fokuserbar och fungerar med Enter/mellanslag och skärmläsare. aria-expanded berättar om menyn är öppen eller stängd.
  10. innerHTML tolkar texten som HTML, så kod från användare kan köras (XSS). textContent sätter alltid bara text.
